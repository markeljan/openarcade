# Fidelity priorities: selected later catalog games

This is a bounded comparison captured on 2026-10-28, not a parity audit. The reference pages were loaded in REA-controlled headless Edge at 1280 × 720 with reduced motion. For each, REA pressed Enter twice, Right, and Space, then captured a screenshot after 0.5 seconds. The local run opened the named gallery card, clicked Play, pressed Right and Space on the canvas, and captured after 0.5 seconds. These are short, agent-driven manual-input probes: they do not establish full win/loss behavior, a complete playthrough, timing equivalence, or the effects of keys that were not exercised. Reference claims below beyond those screens come from static inspection of the shipped page source, not from those probes. No game is claimed to be exact.

Reference and local REA evidence IDs below identify those two controlled runs. The screenshots, action outcomes and page-error capture were observed; the listed scenarios completed without captured page errors. In the Neon Vow reference probe the help overlay remained visible after the rapid Enter presses, so it did **not** establish active-play response to Right or Space. Inspect it again with deliberate waits and a complete run before drawing runtime conclusions.

## Evidence limits and next validation

The screenshots are starting-state samples, not proof of a complete interaction. The reference HTML was inspected as shipped page source and the local behavior as source in the linked files; those static rules do not prove every branch ran in these sessions. To turn priorities into verified changes, record a longer manual scenario per title that reaches one meaningful outcome (gate opening, stamped decision, feeding/rescue, room clear, salvo or rewind), then add a focused regression for the independently implemented local counterpart. Avoid deriving exact timing, collision geometry or full content coverage from these probes.
